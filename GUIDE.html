Event Board — Run & Verification Guide

Sprint 3 Refactoring · CS326 Team Project

1. Prerequisites

  • Node.js ≥ 18 and npm
  • A terminal in the project root (CS326-project-event-board/)

2. First-Time Setup

npm install
npx prisma generate
npx prisma migrate deploy
migrate deploy applies the three existing migrations and creates prisma/dev.db. If the DB already exists and has all tables, you can skip this step.

3. Running the App

In-memory mode (default — data resets on restart)

npm run dev

Prisma mode (persistent SQLite)

MODE=prisma npm run dev

The app starts at https://localhost:3443 (HTTP on 3000 redirects to HTTPS). A self-signed certificate warning will appear in the browser — accept it to proceed.

Note: In Prisma mode the database starts empty — there are no seed events. You will need to create and publish at least one event to test most features.

5. Feature Verification Checklist

Feature 1 — Create Event

  1. Log in as staff@app.test.
  2. Navigate to /events/new.
  3. Fill in all required fields (Title, Description, Location, Start/End datetime). Submit.
  4. Expected: Redirected to the new event's detail page. Status badge shows draft.
  5. Try submitting with an empty title — Expected: validation error shown inline.

Feature 2 — Event Detail Page

  1. From the event list (/events) or directly via URL, open any event.
  2. Expected: Title, description, location, category, start/end times, organizer, and attendee count are all displayed.
  3. As admin viewing a draft event: Edit, Publish, and Cancel controls appear in the sidebar.
  4. As user@app.test viewing a published event: RSVP button and Save button appear.

Feature 3 — Event Editing

  1. Log in as staff@app.test (or admin). Open a draft or published event you own.
  2. Click Edit. The edit form pre-fills with current values.
  3. Change the title and click Save Changes.
  4. Expected: Redirected to the updated event detail page with the new title.
  5. Try submitting with an empty location — Expected: error shown, form retains other values (HTMX inline update).

Feature 4 — RSVP Toggle

  1. Log in as user@app.test. Open a published event.
  2. Click RSVP — Expected: button changes to Cancel RSVP.
  3. Click Cancel RSVP — Expected: button reverts to RSVP.
  4. As admin or staff: RSVP button should not appear (roles cannot RSVP).

Feature 5 — Event Publishing

  1. Log in as staff@app.test. Open a draft event you created.
  2. Click Publish — Expected: status badge changes to published; Publish button disappears, Cancel button appears.
  3. Click Cancel Event — Expected: status changes to cancelled. A cancellation notice is shown.

Feature 6 — Category / Date Filter (Event List)

  1. Navigate to /events.
  2. Select a category from the dropdown (e.g., Tech) and click Filter.
  3. Expected: Only events in that category are shown (HTMX partial update, URL updates).
  4. Select a Timeframe (e.g., This week) — Expected: events filtered to the current week.
  5. Type a search term in the Search field — Expected: matching events shown by title/description/location.
  6. Click Clear to reset — Expected: all upcoming published events shown.

Feature 7 — RSVP Dashboard

  1. Log in as user@app.test. RSVP to at least one published event.
  2. Navigate to /rsvps/dashboard.
  3. Expected: Upcoming section shows events with "Going" or "Waitlisted" status. Past & Cancelled section shows older RSVPs.
  4. Click Cancel RSVP on an upcoming entry — Expected: row updates in place (HTMX) to show Cancelled status.
  5. Log in as admin and try to access the dashboard — Expected: 403 Forbidden.

Feature 9 — Waitlist Promotion

  1. Create a published event with Capacity = 1 as staff.
  2. Log in as user@app.test and RSVP — Expected: status is Going.
  3. Create a second user account via /admin/users (role: user).
  4. Log in as the second user and RSVP to the same event — Expected: status is Waitlisted. Waitlist position (#1) appears on the detail page.
  5. Cancel the first user's RSVP — Expected: second user is automatically promoted to Going.

Feature 10 — Event Search

  1. Navigate to /events.
  2. Type a keyword in the Search box (e.g., part of an event title). Press Enter or click Filter.
  3. Expected: Matching events appear. URL updates to /events?q=keyword.
  4. Clear the search — Expected: full list restored.

Feature 11 — Past Event Archiving

  1. Navigate to /events/archive.
  2. Expected: Events with status past or a past end datetime are listed. In memory mode, two seed events appear here.
  3. In Prisma mode: manually set an event's end datetime to the past via the edit form, or use the PastEventArchiving service to trigger archiving.

Feature 14 — Save for Later

  1. Log in as user@app.test. Open any published event.
  2. Click Save in the sidebar — Expected: button changes to Saved ✓ (HTMX partial update).
  3. Navigate to /saved — Expected: saved event appears in the list.
  4. Click Remove on the saved event — Expected: event disappears from the saved list.
  5. Confirm toggling save from the event detail page also works.

8. Resetting the Database

To wipe all data and start fresh in Prisma mode:

rm prisma/dev.db
npx prisma migrate deploy
